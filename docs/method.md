# 方法说明: 这个仓库里值得借鉴的三个设计

本仓库的价值不在"提出新算法"（PPO、Lyapunov 优化都是成熟技术），
而在于把几项成熟技术组合到"多 UAV + HAP 边缘计算卸载"这个具体场景时，
给出的**工程化参考实现**。本文按设计决策逐一说明: 解决什么问题、怎么实现、
什么情况下可以复用。所有代码位置均指仓库根目录下的文件。

> 阅读顺序建议: 先看 README 了解场景，再对照本文浏览代码。

---

## 0. 场景与决策问题

```
地面 IoT 任务(泊松到达, 85% 集中在 4 个波束热点)
        │ 上行
        ▼
   HAP(高空平台) ── 4 个固定波束, 任务按最近波束聚成"簇"
        │
        │ 5G 飞行 + 卸载
        ▼
10 架异构 UAV(算力 1/5/10 GHz 三档, 5:3:2 配比) 每时隙决策:
   a = 0       机载计算(覆盖内有零散任务则本地算, 否则打包经 HAP 中继)
   a = 1..4    飞向对应波束簇, 承接整个簇的任务
```

难点(也是它比"单机 MEC 教材仿真"难的地方):

1. **多时隙耦合**: 一次"飞行 + 传输 + 计算"要 10~20 秒 ≈ 2~4 个时隙,
   决策后 UAV 长时间不可用, 奖励也是延后结算的;
2. **长期约束**: 要求长期平均能耗不超过 E_AVG, 而单步奖励里没有这一项;
3. **异构性**: 算力差 10 倍的 UAV 用同一个策略学习, 高算力机经验会淹没低算力机。

对应的三个设计决策如下。

---

## 1. Lyapunov 虚拟队列: 把长期约束变成"看得见的状态"

### 解决什么问题

"长期平均能耗 ≤ E_AVG" 是时域耦合的约束, 单时隙 RL 无法直接表达。
经典做法是 Lyapunov(漂移+惩罚) 框架: 引入虚拟队列把约束变成动态系统。

### 本仓库的实现

维护两个标量虚拟队列 (`env.py` 的 `_update_lyapunov_queues`):

- **能耗债务** Z(t+1) = max(0, Z(t) + E_total(t) − E_AVG): 能耗超支时增长;
- **处理率债务** Y(t+1) = max(0, Y(t) + λ_arrive − service_rate): 处理跟不上到达时增长。

与教材上"把 Z 乘进奖励"的教科书做法不同, 本仓库的取的是更保守的组合:

- Z、Y **进入观测向量** (观测构造见 `env.build_state_vector` 的 Q/Z/Y 三维);
- 奖励只做**逐步整形** (`env.end_of_step` 第 3 步):
  任务量奖励 − 距离惩罚 − 负载贡献奖励 − 归一化时延惩罚 − 归一化能耗惩罚。

时延/能耗惩罚用**常量参考值** (`REF_DELAY`/`REF_ENERGY`) 归一化, 而不是按
task_vol 缩放——原实现踩过坑: 按 task_vol 缩放时, 多 UAV 场景下单机分到的
任务变小, 惩罚项被过度放大, credit assignment 崩掉。

### 何时可复用

- 长期平均约束(能耗/队列/时延上界) + RL: Z/Y 队列进观测, 让策略自己学会
  在"债务高"时收敛, 比硬调奖励权重稳;
- 多智能体共享大场景: 惩罚项用常量参考值归一化, 避免个体规模差异放大噪声。

## 2. 参数共享 + ID embedding + 均衡采样: 异构群体的单策略学习

### 解决什么问题

10 架 UAV 算力差 10 倍, 最优行为模式不同(高算力飞远簇, 低算力就近),
但每个智能体的数据量又不足以独立学习。

### 本仓库的实现

三层结构 (`networks.py`, `balanced_buffer.py`):

1. **参数共享**: 所有 UAV 用同一套 Actor/Critic;
2. **身份嵌入**: `nn.Embedding(num_uavs, 16)` 把 UAV ID 变成 16 维向量,
   与状态拼接后进 MLP——网络因此能区分"这是低算力 3 号"并输出差异化策略;
   注意原生观测里不含 ID, ID 只在网络侧注入;
3. **均衡采样缓冲区** `PerUAVBalancedBuffer`: 每个 UAV 独立存经验,
   每次更新从各缓冲区**等配额**抽取 batch/N 条再打乱混合
   (`balanced_buffer.sample`)。若混合采样新, 高频决策/高回报的 UAV
   会主导梯度, 均衡配额让每个"身份"对梯度的贡献相同。

配套一致性: 采样时的**动作掩码随经验存储**, PPO 更新复算新旧对数概率时
用同一掩码 (`ppo_trainer.update` 调 `actor.evaluate_actions(..., action_mask)`)。
否则新旧策略 ratio 是在两个不同合法集上算的, clip 目标失真——这是原实现
修掉的一个真实不一致。

### 已知简化(诚实声明)

`ppo_trainer.update` 的 GAE 递推是在打乱后的批次上做的, 样本来自不同 UAV、
不同时隙, 严格说是"带折扣的混合优势估计"而非逐轨迹 GAE。工程上能收敛,
但若做严肃对比实验, 建议按 (UAV, episode) 分组重写递推顺序。

### 何时可复用

- 异构智能体群体 + 数据量不足以分策略学习: 参数共享 + ID embedding;
- 群体行为频率/回报分布不均: 均衡配额采样;
- 环境有非法动作(如不可行簇组合): 掩码随经验存储, 保证 ratio 一致性。

## 3. 多时隙任务模型: 忙碌状态机 + 时隙末结算 + 动作掩码

### 解决什么问题

"飞过去 + 传 + 算"跨 2~4 个时隙: 决策时刻与任务完成时刻分离,
奖励要延后结算, 期间 UAV 不可再决策。

### 本仓库的实现

- **忙碌状态机** (`uav.py`): `start_beam_task`/`start_onboard_task` 把任务
  折算成 `_flight_slots + _compute_slots` 个时隙, 存入 `_pending_*` 字段;
  `tick()` 每时隙推进一次, 飞行阶段线性插值移动;
- **时隙末结算** (`env.end_of_step`): 所有 UAV 决策完后统一 tick、结算中继
  双跳的精确时延/能耗(决策时只有估值)、计算奖励、更新虚拟队列、生成新任务。
  训练循环(`train.run_training`)因此是"内层逐 UAV 决策 → 外层 end_of_step
  → 回填奖励进缓冲区"的两段式结构;
- **动作掩码** (`env.get_action_mask`): 忙碌 UAV 掩码全空(直接跳过),
  空闲 UAV 的波束动作只有在算力允许的可行簇组合包含该簇时才可用
  (`uav.get_feasible_cluster_combinations` 给出单簇/多簇可行组合枚举)。

### 何时可复用

- 任何"动作执行时间长于决策周期"的环境(制造、物流、机器人维护等):
  pending 字段 + tick 状态机 + 决策/结算两段式循环, 是最小可行的改造模板;
- 组合爆炸的动作空间: 先枚举"可行组合"再投影成掩码, 而不是给每个组合一个动作。

## 4. 标准化接口: 让环境可以"即插即用"

`env_wrapper.UavHapMecGymEnv` 把上述多智能体接口包装成标准 Gymnasium
单智能体五元组(`step(action)`), 并注册为 `gym.make("UavHapMec-v0")`,
通过 `gymnasium.utils.env_checker.check_env` 校验。包装的时序约定与
奖励归并的近似性在 docstring 里写明。
目的: 让环境可以被 stable-baselines3 等现成库直接消费,
也可以被你自己的算法直接替换本仓库的 PPO。

`env.py` 的随机性全部走 `env.np_random`(任务生成经 `channel_task.
generate_tasks_at_step(rng=...)` 注入), `reset(seed=N)` 后整个环境
比特级可复现——这是对接 CI 和消融实验的底线要求。

---

## 5. 已知局限

- 波束数固定为 4 (`config.NUM_BEAMS`), 聚类是"最近波束 + 容量上限"的
  启发式, 不含动态波束成形;
- 中继模式用固定双跳模型(地面→HAP→UAV), 通信能耗未计入;
- GAE 批次级近似(见第 2 节);
- 单 HAP、无故障/无恶意节点模型。

欢迎按上面的接口边界替换模块做扩展; 有价值的扩展欢迎提 PR。
